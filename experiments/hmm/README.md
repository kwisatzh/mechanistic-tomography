# Belief State Estimation and One Step Control

This testbed measures how estimation error affects one controller-chosen
activation edit in a transformer trained on two hidden Markov models (HMMs).
The exact filtered posteriors provide an independent reference for estimation
error, while target error and nuisance movement measure the edit's effects.
The retained experiment evaluates one estimate-and-edit step per token position,
not a repeated feedback trajectory.

The code and earlier retained results are unchanged. The artifact additionally
includes recovered specificity records, saved readouts, and a separate CPU
verification. The commands later in this README remain the original fresh-run
entry points; the verification below reuses the checkpoint without training.

---

## What the experiment does

The synthetic environment is a 4-token sequence generated by two independent binary HMMs.

- HMM #1 is the controlled belief variable `z1`.
- HMM #2 is a nuisance belief variable `z2`.
- The token is `o1 + 2*o2`, so the model must track both hidden processes to predict the next token.
- The true posterior log-odds `z1 = logit P(s1_t=1 | observations up to t)` and `z2` are known exactly by Bayesian filtering.

The script trains a tiny causal transformer on next-token prediction only, then:

1. Probes each residual layer for `z1` and `z2`.
2. Chooses an actuation direction for `z1` using high-minus-low posterior activations.
3. Keeps a P controller fixed.
4. Sweeps observers:
   - oracle posterior
   - noisy oracle at several noise levels
   - linear probe
   - coarse posterior-sign proxy
   - entangled observer: `z1 + 0.9*z2`
5. Produces the main plot:

```text
observer RMSE against true z1  vs  target loss after one edit
```

Across the ten retained observer variants, target error after the edit tracks
observer RMSE (Spearman correlation 0.95). The trained linear readout and analytic
posterior give similar control error despite different estimation error; their
small ordering reverses in the CPU verification described below. Agreement with
the reference and usefulness for this edit are assessed separately.

### Measurement accounting

The aggregate-recovery study uses 12 fitting measurements for OMP and 32 for
ridge, with 64 additional validation measurements and 64 separate test
measurements in both cases. Thus its non-test budgets are 76 and 96, respectively;
the 32 singleton reference measurements are additional. The 12-measurement
result is a fitting-budget comparison, not an all-in saving over 32 patches.

### The ten observer variants and their comparison

`observer_predictions` and `run_control_eval` in `hmm_observer_control.py`
define the exact posterior log-odds `z1`, a trained linear readout, the coarse
proxy `1.5 * sign(z1)`, the mixed estimate `z1 + 0.9*z2`, and six versions of
`z1` with zero-mean Gaussian noise at standard deviations 0.25, 0.5, 1, 1.5, 2,
and 3. In `frozen/observer_control.csv`, the trained readout's target MSE is
3.441 and the exact posterior's is 3.484 under the same edit direction. The
separate CPU verification gives 3.4862 and 3.4580, respectively, reversing this
small ordering. Both comparisons show similar control performance despite
different estimation error; they do not establish that the readout controls better.

The separate mixed observer-and-actuator condition uses `z1 + 0.5*z2` and a
direction proportional to `d1 + 0.5*d2`. It reduces target MSE from 25.02 to
4.81, compared with 3.56 for target-only oracle control, while off-target probability movement
increases from 0.037 to 0.079. This is a different comparison from the ten-observer
fixed-direction sweep; the two oracle values should not be interchanged.

### Recovered specificity record and CPU verification

The original eight-row CSV is now retained under `frozen/gate_d_rotating_v1/`.
It verifies the rounded numbers above. The separate CPU run in
`frozen/specificity_cpu_verification/` gives target MSE 25.1707 before editing
and 4.7808 after the mixed edit, with oracle MSE 3.4580. Mean absolute off-target
probability movement is 0.03656 for the oracle and 0.07912 for the mixed edit.

The relevant column is `collateral_q2_abs`: absolute change in the second chain's
next-observation probability. The alternative column `collateral_z2_abs` measures
implied-log-odds movement and does not show the same increase: it changes from
3.0506 to 2.8866 historically and from 3.0361 to 2.9091 on CPU. The result is
metric-dependent, as stated in the paper's main text as well as its experimental
details. The historical fixed-direction result is one comparison, not a reliable
ranking across samples.

### The implemented control sequence

In `hmm_observer_control.py`, `run_control_eval` first runs the unedited token
sequence and computes the observer estimate at each position. The fixed
proportional controller converts the gap between that estimate and the target
into an edit size, using the fixed direction's readout gain and the configured
clipping limit. A second forward pass applies those edits and scores the outputs.
All position-specific edit sizes come from the unedited pass; the controlled
outputs do not feed another observer update or an autoregressive rollout.
`control_gate_d_rotating.py` uses the same single estimate-and-edit sequence for
the mixed observer and actuator specificity comparison.

The legacy identifier `last_obs_proxy` in `observer_predictions` returns
`1.5 * torch.sign(z_true)`, where `z_true` is the exact posterior log-odds after
filtering the observation history. It is a coarse posterior-sign estimate, not
an estimate made from the current observation alone. The identifier, historical
source comment, and saved rows are retained for reproducibility; this explanation
supersedes their last-observation wording. Likewise, any closed-loop labels in
historical plotting code or images refer to the one-step measurement above.

## How to read the results

Open these files first:

```text
learning_curve.png
probe_by_layer.png
observer_rmse_vs_control_loss.png
control_loss_vs_collateral.png
summary.json
```

### Gate A: Did the model learn the HMM?

Look at `learning_curve.png` and `learning_curve.csv`.

Useful signs:

- model CE approaches Bayes CE;
- final `bayes_gap` is small, ideally below `0.03–0.08` nats for this toy setup.

If the model has not learned the Bayes filter, the control result is not meaningful. Increase `--steps`, `--d-model`, or use the H100 setting.

### Gate B: Is the posterior linearly visible?

Look at `probe_by_layer.png`.

Useful signs:

- best-layer `z1` probe R² is clearly positive, ideally `>0.7` in a clean run;
- `z2` is also decodable, because it gives the collateral/nuisance check teeth.

If the probe R² is poor, the model either undertrained, did not encode the posterior linearly, or the task is too weak.

### Gate C: Does observer quality matter for control?

Look at `observer_rmse_vs_control_loss.png`.

Useful signs:

- oracle is near the lower-left;
- noisy-oracle points form a roughly increasing curve;
- linear probe lands near its observer RMSE on that curve;
- bad/entangled observers are worse and/or cause more collateral movement.

This is the key falsifier. If all observers have the same control loss, observer fidelity was not binding in this task/controller/actuator channel.

### Gate D: Is the controller specific?

Look at `control_loss_vs_collateral.png`.

Useful signs:

- good observers improve controlled belief `z1` with low movement in nuisance marginal `q2`;
- entangled observers move `q2` more.

This matters because a confounded-but-causal knob can be control-useful without identifying the intended belief state.

## Decision rules

After the first local baseline:

### Continue if

- model CE is close to Bayes CE;
- `z1` is decodable from at least one residual layer;
- observer RMSE and control loss have a visible positive relationship;
- bad/entangled observers produce worse control or more collateral damage.

### Do not continue yet if

- training is underfit;
- probe R² is near zero;
- the actuation direction has near-zero gain;
- control does not change the output distribution;
- every observer performs identically.

In that case, fix the harness before building an NT observer.

## Possible next checks if Figure 1 works

1. **Observer sweep with structured corruption**
   - Add `z_hat = z1 + alpha*z2` for many `alpha` values.
   - Plot collateral movement versus entanglement.

2. **Target sweep**
   - Run `--target-z -2`, `0`, `2`, and maybe random target signs.
   - Check whether the relationship is symmetric.

3. **Layer sweep**
   - Hold observer type fixed and vary control layer.
   - Ask whether the best observer layer is also the best control layer.

4. **Active-tomography prototype**
   - Given uncertain observer estimates, append one controlled extra observation bit.
   - Choose the bit expected to maximize posterior separation.
   - Compare passive probe versus active probe under the same controller.

## Notes on scope

This experiment links observer quality to one-step control performance in a
small model with an exact posterior reference. It also separates fidelity to that
reference from usefulness for the implemented edit. It does not test stability
or performance over repeated feedback updates, or establish belief identity in
a pretrained LLM.
